# 나에게 맞는 곳 — 맞춤 추천·산책 코스 화면

「서울숲, 머무는 숲」 대시보드에 더한 세 번째 화면입니다. 컨셉은 **개인의 니즈에 따른 공간 추천과 산책 루트 찾기**입니다.

기존 대시보드는 빌드된 파일만 있고 React 소스가 이 폴더에 없어서, 대시보드 본체는 건드리지 않고 **따로 도는 정적 페이지**로 만들었습니다. 기존 대시보드의 자료(`../data/`)와 스타일(`../assets/index-*.css`)을 그대로 읽어 씁니다. 빌드 과정이 없으므로 파일을 고치면 바로 반영됩니다.

## 화면

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 시민 화면 | `needs/` 또는 `needs/#citizen` | 하고 싶은 일·머물 시간·같이 온 사람을 고르면 갈 곳 3곳을 이유(그늘, 화장실 거리, 붐빔, 몇 시까지 머물 수 있는지)와 함께 추천. 가는 길 또는 산책 코스(20·40·60분)를 그늘·쉼터·계단 없음·한산함 조건으로 짜 줌. 서울숲이 맞지 않으면 근처 무료 장소(도서관·주민센터·공원)를 보여 줌 |
| 관리자 화면 | `needs/#admin` | 20m 칸마다 앉을 곳·그늘·화장실·붐빔을 견주어 쉬기 어려운 곳과 이유를 지도에 표시. 벤치·그늘·화장실을 어디에 놓으면 가장 많이 줄어드는지 계산하고 CSV·GeoJSON으로 내려받음. 현장 조사 시설 입력, AI 보고·질문 |

시연용 주소 옵션: `?s=heat|dust|rain|cold`(날씨 상황), `?t=3-14`(요일-시각. 0=일 … 6=토). 예: `needs/?t=6-14` 는 토요일 오후 2시.

## 여는 법

- 배포본: `recovery-station/` 폴더째 올리면 `…/recovery-station/needs/` 로 열립니다. 기존 대시보드 위쪽 탭 줄에 「3 나에게 맞는 곳」이 생깁니다.
- 내 컴퓨터에서: 파일을 더블클릭하면 안 열립니다(모듈과 자료를 불러올 수 없음). `recovery-station` 폴더에서 `python -m http.server 8000` 을 실행하고 `http://localhost:8000/needs/` 로 엽니다.

## 기존 대시보드와의 연결

기존 대시보드에서 바꾼 것은 `recovery-station/index.html` 에 넣은 한 줄뿐입니다. 원래 파일은 `index_수정전.html` 로 남겨 두었습니다.

```html
<script src="./needs/link.js" defer></script>
```

**대시보드를 다시 빌드하면 이 줄이 사라집니다.** React 소스에서 아래처럼 해 주세요.

1. `needs/` 폴더를 프로젝트의 `public/needs/` 에 넣습니다. Vite는 `public/` 을 그대로 복사합니다.
2. 탭 줄 컴포넌트에 링크를 직접 넣고 `link.js` 는 지웁니다. 소스의 `index.html` 에 위 한 줄을 넣어도 됩니다.
   ```jsx
   <a className="tab goal-tab g3" href="./needs/"><span className="tab-n">3</span>나에게 맞는 곳</a>
   ```
   링크를 직접 넣을 때는 `link.js` 안의 `--goal3` 색과 `.goal-tab.g3 .tab-n` 규칙을 대시보드 CSS에 옮깁니다.
3. 빌드하면 CSS 파일 이름(`index-CS1fLUE9.css`)이 바뀝니다. `needs/index.html` 의 `<link href="../assets/index-….css">` 를 새 이름으로 고칩니다. 고치지 않아도 `base.css` 로 넘어가 화면은 그대로 나오지만, 대시보드 디자인을 바꾼 경우에는 옛 모습으로 남습니다.
4. 이 화면이 읽는 대시보드 자료: `data/park.geojson`, `grid.geojson`, `network.json`, `features.geojson`, `context.geojson`, `hubs.json`, `team.json`, `meta.json`. 이 파일들의 구조를 바꾸면 `js/model.js` 를 맞춰야 합니다.

탭 이름(「나에게 맞는 곳」, 「목표 3」)은 `link.js` 와 `js/main.js` 에서 바꿉니다. 테마(라이트·다크)는 기존 대시보드와 같은 저장 이름(`sf-theme`)을 써서 함께 바뀝니다.

## 계산 방법

### 갈 곳 추천 (`recommend.js`)

- 거점 14곳마다 점수를 매깁니다. 비중은 하고 싶은 일 35 · 머물 수 있는 시간 20 · 같이 온 사람 15 · 붐빔 12 · 날씨에 맞는 자리 10 · 걷는 거리 8 · 화장실 5 입니다. 혼자면 붐빔을, 아이·어르신과 함께면 화장실과 걷는 거리를 더 봅니다.
- **머물 수 있는 시간**은 운영 시간 → 밤 → 날씨 → 추위 순으로 따져 지금부터 몇 시까지 되는지 셉니다(12시간 앞까지).
- 추천 순서: 지금 조건에 맞는 곳 → 갈 수는 있지만 붐비거나 시간이 짧은 곳 → 3시간 안에 갈 수 있게 되는 곳 → 그보다 뒤에 가능한 곳(밤에는 내일 아침). 사정은 카드에 노란 꼬리표로 적습니다.
- 꼭 맞는 곳이 3곳이 안 되면 근처 무료 장소를 펼쳐 보여 줍니다. 날씨가 나쁘면 실내(도서관·주민센터)를, 붐빌 때는 공원을 먼저 보여 줍니다.

### 길과 산책 코스 (`route.js`)

- 보행망(`network.json`)에서 가장 짧은 길을 찾고, 고른 조건에 따라 구간 비용을 바꿔 다시 찾습니다. 그늘은 칸의 나무 그늘 비율, 한산함은 구간 혼잡 추정값, 계단 없음은 계단 구간 제외, 쉼터는 쉼터 사이가 먼 구간에 쉼터를 끼워 넣는 방식입니다(가장 짧은 길의 1.35배까지만 돌아감).
- 추운 날(체감 12℃ 미만)에는 「그늘」 조건이 「볕 드는 길」로 바뀝니다. 해가 진 뒤에는 꺼집니다.
- 산책 코스는 공원 안에 고루 퍼진 지점 44곳과 쉼터·거점을 한두 곳 거쳐 목표 길이에 가장 가까운 길을 고릅니다. 같은 길을 되짚거나 공원 밖으로 나가는 길은 벌점을 주고, 남으면 화면에 몇 m인지 적습니다.
- 휠체어·유모차를 고르면 계단을 피하고 시속 3.2km로 계산합니다(기본 4.2km).

### 쉬기 어려운 곳 (`rest.js`)

- 팀 20m 격자 1,003칸(40.1ha, 보류 94칸 제외)마다 네 가지를 봅니다.

  | 항목 | 일반 이용자 | 어르신·유아 |
  |---|---|---|
  | 앉을 곳까지 걷는 거리 | 150m 안 | 100m 안 |
  | 화장실까지 걷는 거리 | 250m 안 | 150m 안 |
  | 나무 그늘 | 30% 이상 | 50% 이상 |
  | 붐빔 지수 | 60 미만 | 50 미만 |

- 두 가지 이상 어긋나면 「쉬기 어려운 곳」입니다. 붙어 있는 칸은 구역으로 묶어 넓이와 이용 정도 순으로 세웁니다.
- 시설 자리는 「놓았을 때 기준 안으로 들어오는 칸이 가장 많은 길 위 지점」을 하나씩 고르는 방식입니다. 그늘은 그늘이 모자라고 사람이 많이 지나는 길가를 고르고, 팀이 앞서 정한 식재 후보 칸과 겹치면 표시합니다.

## 기존 대시보드와 다른 규칙 (이 화면에서 더한 가정)

날씨 단계 기준, 붐빔 추정식, 걷는 속도, 계단 벌점은 기존 대시보드와 같습니다. 아래는 이 화면에서 새로 정한 것이고, 값은 모두 `js/config.js` 에 있습니다.

- **운영 시간**: 곤충식물원·나비정원은 공식 자료로 확인했습니다. 수도박물관·복합문화체육센터·방문자센터·수변휴게실은 확인하지 못해 보수적으로 잡았고 화면에 「운영시간 확인 필요」로 적습니다.
- **밤**: 22시~6시에는 야외 자리를 추천하지 않습니다.
- **추위**: 체감 0℃ 미만이면 야외에 오래 머물기 어렵다고 봅니다(걷기·운동·놀이는 −8℃).
- **비**: 비가 오면 그늘 자리도 머물기 어렵다고 봅니다. 기존 대시보드는 그늘 자리를 비 올 때도 괜찮다고 봅니다.
- **붐빔**: 기존 대시보드는 수용의 85%를 넘으면 머물 수 없는 곳으로 치지만, 여기서는 머물 수 있는 시간과 따로 보여 주고 순서만 뒤로 미룹니다.
- **한파 상황**을 시연용 날씨에 더했습니다.
- **실내 시설의 화장실**: 방문자센터·수변휴게실·복합문화체육센터·수도박물관은 건물 안에 화장실이 있다고 가정했습니다.
- **출발점**: 「서울숲역 방면 입구」 좌표가 광장과 이어지지 않은 골목 끝에 붙어 1.7km를 돌아가는 문제가 있어, 150m 안의 공원 안 길에 붙이도록 했습니다. 기존 대시보드의 길 찾기에도 같은 문제가 있습니다.
- **장소별 적합도**(어떤 곳이 어떤 일에 맞는지)는 팀이 정한 가정값입니다. 설문 결과가 나오면 `AFFINITY` 표를 바꿉니다.

## 자료와 한계

- **앉을 곳은 실제보다 훨씬 적게 잡혀 있습니다.** OpenStreetMap에 등록된 벤치·정자·실내 휴게실 6곳만 반영됩니다. 그래서 일반 기준에서 「앉을 곳이 멂」이 857칸(85%)으로 나오고, 쉬기 어려운 곳 516칸(51%)이라는 숫자도 이 영향을 크게 받습니다. 발표에서는 「현장 조사 전 추정」이라고 밝혀야 합니다. 관리자 화면의 「현장 조사로 시설 추가」에서 벤치를 넣으면 바로 다시 계산됩니다.
- 붐빔은 실제로 센 값이 아니라 요일·시각·날씨로 어림한 값입니다.
- 나무 그늘은 여름 위성 영상 기준이라 겨울에는 다릅니다.
- **습지생태원 구역(도로 건너 북쪽)은 팀 20m 격자 밖입니다.** 그래서 「쉬기 어려운 곳」 판정과 시설 제안에서 빠져 있고, 습지생태원은 추천 카드에 그늘 비율 대신 「그늘 자리 · 분석 범위 밖이라 그늘 비율은 모름」으로 나옵니다. 그쪽으로 가는 길의 그늘 비율도 격자 안 구간만으로 셉니다.
- 근처 무료 장소는 OpenStreetMap 기준이라 빠진 곳이 있을 수 있고, 운영 시간은 종류별 어림값입니다(주민센터 평일 9~18시, 도서관 9~18시). 성수도서관은 서울시 미디어허브 기사로 위치를 확인했습니다.
- 날씨는 Open-Meteo 예보·대기질 모델값입니다. 연결이 안 되면 표본 날씨로 바뀌고 화면 아래에 그렇게 적힙니다. 시연용 시각을 고르면 실제 예보 대신 표본 날씨를 씁니다.
- 지도와 시설: © OpenStreetMap 기여자 (ODbL).

`data/` 를 다시 만들려면 프로젝트 폴더에서 `python -I analysis/06_needs.py .` 을 실행합니다.

## 현장 조사 자료 반영

1. 관리자 화면 → 「현장 조사로 시설 추가」 → 종류를 고르고 「지도를 눌러 넣기」.
2. 넣은 시설은 그 브라우저에만 저장됩니다.
3. 모두에게 반영하려면 「조사 자료 내려받기」로 받은 `survey.json` 을 `needs/data/survey.json` 과 바꿔 올립니다.

## AI

관리자 화면의 「AI에게 맡기기」는 Claude가 진단 결과를 읽고 관리자용 보고를 쓰거나 질문에 답하는 기능입니다. AI 없이도 계산으로 뽑은 요약은 항상 보입니다.

- 모델: `claude-opus-5-5` (`js/config.js` 의 `AI.model`). 공식 Anthropic SDK(`@anthropic-ai/sdk` 1.8.0)로 부르고, 답은 오는 대로 화면에 이어 붙입니다.
- **API 키는 쓰는 사람이 직접 넣습니다.** 키는 그 브라우저에만 저장되고(기본은 탭을 닫으면 지워짐) Anthropic API로만 보냅니다. 요금은 키 주인 계정에 붙습니다.
- 보내는 것: 진단 집계값, 구역·제안 자리의 장소 이름, 질문. 화면의 「AI에 보내는 자료 보기」에서 그대로 확인할 수 있습니다. 개인정보는 없습니다.
- 모델이 답을 거절하면 Anthropic이 정한 다른 모델이 이어서 답하도록 하는 설정(server-side fallback)을 켜 두었습니다. 그렇게 답한 경우 화면에 적힙니다.
- 브라우저에 키를 넣는 방식은 시연과 내부 사용에만 맞습니다. 누구나 쓰는 서비스로 열려면 키를 서버에 두고(예: Supabase Edge Function) 그 서버를 거쳐 부르도록 `js/ai.js` 를 바꿔야 합니다.
- 실제 키로 호출해 보지는 못했습니다. 요청 형식, 오류 안내(키 없음·잘못된 키·모델 없음·거절), 답 표시는 모의 응답으로 확인했습니다.

SDK 묶음 파일을 다시 만들려면:

```
npm i @anthropic-ai/sdk esbuild
echo "import Anthropic from '@anthropic-ai/sdk'; export default Anthropic;" > entry.mjs
npx esbuild entry.mjs --bundle --format=esm --platform=browser --target=es2022 --minify --legal-comments=none --outfile=vendor/anthropic-sdk.mjs
```
