## 학습목표별 실측

### 01 구별할 수 있다 — 화면과 응답 (슬라이드 6~7)

같은 조문을 두 주소로 물었다.

| | 웹페이지(사람용) | API 응답(프로그램용) |
|---|---|---|
| 받은 것 | HTTP 200 · text/html · **1,297바이트** | HTTP 200 · application/json · **7,972바이트** |
| 조문 글자 | **없음** — frame 1개·script 2개만 옴 | **있음** — 기본정보 20칸 + 조문이 항·호·목으로 나뉨 |

웹페이지 주소만 받아서는 조문을 얻을 수 없다. 본문은 브라우저가 다른 주소에서 다시 불러와 그리기 때문이다.

### 02 해부할 수 있다 — 주소 한 줄의 네 부분 (슬라이드 8)

```
https://www.law.go.kr  /DRF/lawSearch.do  ?target=law&type=JSON&query=...  &OC=${LAW_OC}
   도메인                    경로                   파라미터                    인증키
```

경로가 `lawService.do` 로 바뀌면 파라미터도 `query` 대신 `MST` 와 `JO`(여섯 자리)를 받는다.
한글 질의는 `%EA%B5%AD%ED%86%A0...` 로 부호화되어 전송된다.

### 03 판정할 수 있다 — 거절 응답 (슬라이드 9)

| 요청 | HTTP | 본문 | 판정 |
|---|---|---|---|
| C1 등록되지 않은 OC 로 lawService | 200 | 사용자 정보 검증에 실패하였습니다 | 계정·IP 문제 |
| C2 OC 를 빼고 lawSearch | 200 | 필수입력요소 검증에 실패하였습니다 | 파라미터 문제 |
| C3 없는 조 번호 `JO=999900` | 200 | **result·msg 칸 없음** · 2,883바이트 · 조문 0개 | 문구 없이 실패 |

세 경우 모두 HTTP 200 이다. 상태 코드가 아니라 본문의 `result`·`msg` 를 읽고,
그 칸이 없을 때는 받은 조문을 요청과 대조해야 판정할 수 있다.

## 말로 조문을 받는 네 단계 (슬라이드 11~12)

| 단계 | 받은 값 |
|---|---|
| 01 법령 찾기 | 검색 3건 중 제명이 정확히 일치하는 **법률** 선택 |
| 02 식별자 확인 | 법령ID 009294 · MST 284013 · 시행 2026-07-01 · 국토교통부 |
| 03 조문 받기 | `JO=003600` → 제36조(용도지역의 지정) ①② |
| 04 시점 기록 | 시행 2026-07-01 / 조회 2026-09-21 |

응답에 **조회일 칸은 없다.** 서버가 주지 않는 값이므로 호출한 쪽이 직접 적어야 한다.

## MCP 연결 상태

이 PC 에 Node.js 가 없어 배포된 구현체를 쓰지 못하고, **파이썬 표준 라이브러리만으로 MCP 서버를
직접 작성해 붙였다.** 그래서 도구 이름이 `law_search` · `law_detail` · `law_history` 로
강의자료의 `search_law` · `get_law_text` 와 다르지만 역할은 같다.
서버 코드와 설정은 저장소 바깥에 두어 git 이 추적하지 않는다.

## 인증키

이 저장소에 개인 인증키는 없다. 개인 OC 는 아직 발급 전이라 이번 조회는 법제처 공개 데모 키
`OC=test` 로 했고, 키는 환경변수 `LAW_OC` 로만 넘긴다.
개인 키 신청 시 등록할 실습 컴퓨터의 공인 IP 는 `203.237.200.7` 로 확인했다.

## 강의자료 대조

12쪽 예시는 「제36조(용도지역의 **변경**)」 으로 적혀 있으나 원문 조제목은 「제36조(용도지역의 **지정**)」 이고,
예시 본문의 세 항목도 제36조에 없다. 해당 쪽은 AI 생성 이미지이므로 **생성물 오기**로 적는다.
