## 항목별 내용

**① 버제스(1925) 동심원 이론을 종로에 대입**
상업·업무 밀도는 중심에서 바깥으로 244 → 31동/km²로 단조 감소해 이론과 맞지만,
주거는 2–3 km에서 최저인 U자형이라 어긋난다. 북악산·인왕산과 경복궁·창덕궁이
그 권역에 들어와 지대가 끊기기 때문이다.

**② 1 km 링별 건물밀도**
개수가 아니라 밀도(동/km²)로 환산. 개수로는 4–5 km(11,447동)가 가장 많지만
밀도는 0–1 km 1,263 > 1–2 km 940 > 2–3 km 407 ≈ 4–5 km 405 > 3–4 km 385로 순위가 뒤집힌다.

**③ 스마트공원 요소 우선순위**
효과 × 난이도 2축, 요소 12개. 효과 대비 난이도가 낮은 쿨링포그·환경센서·보행 카운터·
스마트 가로등을 먼저 깔고, 디지털트윈·빗물 저류·스마트 화장실은 전략 과제로 미룬다.

**④ 산출물·출처 기록 (PDF 5쪽)**
산출물 4건의 파일 위치와 조회일, 데이터 출처·수집 범위·질의 원본·분류 기준,
보관 위치와 재현 명령을 한 쪽에 표로 정리했다.

## 이전 버전과 달라진 점

이 폴더는 2026-09-20에 **클라크(1951) 밀도경사 모델 · 500 m 링 버전에서 동심원 이론 · 1 km 링
버전으로 교체**했다. 이전 산출물은 git 이력(`097b405` 이전)에 남아 있다.

수치 기준도 다르다. 저장소 최상위 `README.md`의 분석은 POI·건물명·용도영역을 결합한
6단계 판정으로 미분류를 45.1%까지 낮췄고, **이 폴더는 `building` 태그 값만 사용해
미분류 74.4%(용도 기재율 25.6%)** 로 집계했다. 같은 대상지의 수치를 나란히 볼 때는
이 분류 기준 차이를 먼저 확인해야 한다.

## 다시 만들기

```
py src/analyze.py --refresh      # Overpass 조회 → 용도 분류
py src/ring_density.py           # 1 km 링별 밀도 집계 → CSV
py src/build_assignment.py       # PDF 5쪽(PPTX) + 우선순위 CSV
py src/make_map.py               # 참고 지도 HTML
```

`src/queries/*.overpassql`를 그대로 실행하면 같은 원본 데이터를 다시 받을 수 있다.
저장소 최상위 `scripts/assignment_week2.py`는 이전(클라크 모델) 버전 생성기이므로,
실행하면 이 폴더의 PDF·CSV를 예전 내용으로 덮어쓴다.
